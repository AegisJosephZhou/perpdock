# Perpex 市场测试文案与访谈设计

2026-10-14。依据同目录 BRIEF.md；本文件仅准备内容，没有访问账号或发布。X 中英文为二选一的原创帖候选，不建议同平台同时发布两条同义内容。平台可发送条件由 REVIEW.md 和主控结合实际页面判断。

## 1. X 中文候选

以下代码块是完整正文，无需补标题、链接或标签：

```text
我们在做 Perpex，想减少给 Hyperliquid 合约账户入金的步骤。目前在做需求验证，尚未完成真实资金测试。

你的稳定币在哪条链？现在怎么入金，最卡哪一步？如果愿意参加后续小范围测试，也欢迎留言。
```

正文104个Unicode字符；按当前正文的中日韩字符双权重及标点范围估算为186加权字符，留有普通280上限余量。最终以平台编辑器计数为准。没有把源码或本机演示当作可立即入金的网站。

## 2. X 英文候选

```text
We’re building Perpex to simplify funding a Hyperliquid perps account. We’re validating demand; real-money testing is still pending.

Which chain and stablecoin do you use? What’s the hardest step today? Reply if you’d like to join a future small test.
```

正文252字符，现有正文加权计算同为252；不再追加URL、标签或开场白，发布前由主控检查编辑器计数。英文使用 perps account，避免与 HyperEVM/Spot 余额混淆。

## 3. OK 星球中文候选

```text
给 Hyperliquid 合约账户入金，你最卡在哪一步？

我们在做 Perpex，目标是减少稳定币入金的操作步骤。现阶段先验证需求、招募后续小范围测试者；本应用的真人钱包签名和真实资金到账还未验收。

想听听大家最近一次实际经历：稳定币在哪条链、是什么币？从哪里开始，经过了哪些操作？最麻烦的是换币、跨链、准备手续费币，还是核对有没有到账？也可能目前的方式已经很顺手。

欢迎评论分享；如果愿意参加后续测试，也可以直接留言“愿意测试”。现在不需要转账或连接钱包。
```

保留“现有方式已经顺手”的选项，避免只收集赞同意见。现阶段不把“7网络9路线”当作真人钱包或移动端已经验收的承诺；不写免Gas、零手续费、收益或空投。

## 4. 三个简短访谈问题

优先回应对方已经提供的内容；一次只追问一个缺失信息，不把三问机械复制到每条评论。

1. 回想最近一次给 HL 合约账户入金：你从哪条链、哪种币开始，实际经过了哪些步骤？
2. 哪一步最费时间或让你不放心？如果都很顺手，现在用什么方法就够了？
3. 如果后续有小范围测试，你愿意试吗？你需要先确认哪一件事才会考虑？

“愿意测试”只记为意向，不等于授权发送私信、连接钱包或转账。不承诺测试时间、收费方案或具体可用功能。对方只谈 HyperEVM/Spot 或普通跨链需求时，先确认其目标是不是默认 Perps 账户，再归类。

## 5. 最小反馈表字段

| 字段 | 填写方式 |
| --- | --- |
| 记录时间、平台、公开讨论链接 | 用于回看上下文与去重，不另收集个人资料 |
| 使用背景 | 已实际入金 / 想入金但未完成 / 尚无需要；目标是Perps还是其他账户 |
| 来源网络、资产、起点 | 用户原话；起点可为自有钱包或交易所；不要求地址、余额或账户截图 |
| 当前流程 | 用了什么工具、几步；未说明就记“未说明” |
| 主要问题或现有方法已足够的原因 | 保留一句原话，再标换币/跨链/原生手续费/到账核对/其他/无明显问题 |
| 后续测试意向与前提 | 愿意 / 不愿意 / 未表态；用户明确提到的信任或功能要求 |
| 证据类型、下一步 | 实际经历 / 泛泛意见；公开回复已完成 / 待一个澄清问题 / 无需跟进 |

同一公开讨论的重复评论合并为一条反馈。点赞、曝光和泛泛“支持”可另记，但不能计为实际入金痛点或测试报名。仅记录自愿提供的公开反馈，不索要私钥、助记词、验证码、订单访问令牌或转账。

## 6. 回贴取舍建议

只回应明确正在讨论 HL 合约账户入金、相关链上稳定币或实际换币/跨链步骤的上下文。先回答对方问题、承认其已有方法，再视上下文用一句“我们在做 Perpex，正在验证这个需求”说明关联；只追问一个具体问题。不在价格预测、收益展示或无关新闻下插入招募。有人要立即可用链接时，如实说明目前没有已确认的公网资金测试入口；源码只能作为代码参考，不能描述成入金入口。

本组未执行任何账号操作；所有发布与回贴由主控逐条读取上下文后决定。
