# Perpex 公开环境验收

更新：2026-10-15。本文记录可公开的交付要求与检查边界；实际部署架构、网络配置、存储位置、访问凭据和运维操作由部署负责人私密管理。

## 先取得可核验的测试环境

部署负责人需提供实际HTTPS测试地址、对应Git提交版本、暂停新入金的状态，以及异常支持联系人。当前尚无已确认完成验收的目标HTTPS环境。代码上传、软件测试通过或已有品牌网站均不能代替新入金模块的目标部署验收。

## 只读检查工具

仓库提供 `npm run verify:deployment`。由部署负责人给出实际HTTPS地址，通过 `--origin` 参数指定，并用 `--report` 指定一份新的检查报告；不要使用示例地址冒充已部署环境。

工具读取页面、构建资源、健康和公开配置，核对HTTPS、安全响应、暂停状态、限额及来源校验。它不创建订单，不连接钱包，不签名或转账。报告应记录实际执行日期和对应版本，失败项目处理后再复查。

`npm run test:deployment` 的40项离线工具测试已通过；该结果验证检查器行为，不代表目标服务器已通过。只读检查也不能证明资金到账、备份可恢复或手机钱包兼容。

## 开放受控测试之前

部署负责人应另行确认真实上游连通、订单保存与恢复，以及首轮链币、钱包、金额范围和异常处理责任。既有订单需要保留，不能用清空数据或重复付款来处理未知状态。

随后由用户本人在自己的设备和钱包完成小额验收，逐项核对来源付款、对应路由、本单默认Perps USDC到账、刷新恢复和收据。每条路线与钱包分别留证；未经验证的组合不因单条成功而自动开放。

当前真实Gasless执行与Perpex收费未实现，不能用普通自付手续费路线通过来宣称只有稳定币就能付款。详细状态见[部署交付要求](DEPLOYMENT-HANDOFF.md)、[当前进度](PROJECT-STATUS.md)和[验收记录](ACCEPTANCE.md)。
