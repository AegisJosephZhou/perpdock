# WalletConnect 扫码连接

2026-10-15 更新：新增六个 EVM 主网的 WalletConnect 连接。用户反馈连接测试成功；本次更新尚不构成代币授权、付款或 Hyperliquid 入账验收。

## 支持范围与操作

- 支持 Ethereum、Arbitrum One、Base、Optimism、Polygon PoS、BNB Chain；资产仍限现有审核路线。
- 付款钱包选择「WalletConnect · 扫码连接」，点击「扫码连接」，用兼容手机钱包扫描并确认。页面显示连接后的地址与网络，用户需自行核对。
- 可以主动复制短期连接链接供兼容钱包使用；未接入品牌专用跳转，不保证所有钱包兼容。
- 浏览器注入钱包仍可使用；Tron 继续使用 TronLink，没有新增 Tron WalletConnect 支持。
- 连接不会自动获取报价、创建订单、授权代币或付款。接收地址归属仍需手动确认，来源链手续费仍由用户承担。

## 管理员配置

1. 在 [Reown Dashboard](https://dashboard.reown.com/) 创建自己的项目，取得 Project ID。它是公开项目标识，不是钱包密钥。
2. 在部署环境设置 `WALLETCONNECT_PROJECT_ID`。当前集成接受 32 位十六进制 ID；留空时 WalletConnect 显示未启用，注入钱包继续可用。无效非空值会在打开订单数据库前阻止启动。样例不包含实际 ID，不应使用共享或示例 ID。
3. Node 服务重新启动以读取更新后的环境；只修改 Project ID 不需要重建前端。两个 Compose 文件都转发该变量；使用公网 Compose 时更新对应环境文件并重新创建应用容器，单纯 `restart` 不会更新容器已注入的环境。保留既有订单密钥与持久化数据。
4. 在 Reown 配置实际 HTTPS origin 的 allowlist，并在目标环境验证。应用 metadata 使用当前网页 origin。[官方 Relay 文档](https://docs.reown.com/cloud/relay)说明 localhost 和 127.0.0.1 可用于本地开发；这不等于远程设备能够访问本地网站。
5. 检查 `/api/config` 是否包含 `walletConnect.projectId`。此接口仅增加必要的公开标识，不转发其他环境变量；配置存在不证明实际配对成功。部署检查器会核对启用状态与 CSP 是否一致。

## 取消、重连与恢复

SDK 按需加载，二维码由本地代码生成。连接等待有超时限制；取消、失败或超时后可以重试，迟到的连接结果不能替换当前钱包。每次显式连接使用独立内存会话，刷新后需重新扫码。

账户、网络或连接变化会使旧报价和接收确认失效；交易继续绑定已确认的钱包 provider。断开不会自动切换为另一只钱包，已有订单、付款记录与恢复保护继续保留。未知签名结果或已提交付款必须恢复原单核验，不能通过重连或重新报价再次付款。

报价按钮现在显示禁用原因。没有已记录付款的过期订单可返回报价准备步骤；用户重新连接钱包（如需）、核对并确认接收地址后获取新报价。已完成的链上授权不会因报价过期或重新报价自动撤销。

配对链接只在当前 UI 内存及用户主动复制操作中使用，不写入页面 URL、订单或日志。SDK 遥测关闭；配置启用时，CSP 只增加指定 relay、Verify 和审核过的公开 RPC 端点，脚本仍限同源。自定义二维码流程依据 [官方 Ethereum Provider 文档](https://docs.reown.com/advanced/providers/ethereum)。
