# Perpex：只持有 U 的入金与收费方案

> 2026-10-14 进展：G02 的只读钱包能力检查已实现并通过软件回归，详情见[本轮研发](CONTINUATION-2026-10-14.md)。这不是零 ETH 付款执行；原零 Gas 保护仍保留，代付服务、收费、批次恢复及新来源验证器仍待完整接入和验收。下文是原设计基线。

状态更新：2026-10-15。当前只读能力检查已实现；以下执行与收费方案仍是待实施设计，尚未接入、启用或完成资金验收。10月15日订单进度改动不放开零原生币付款。

## 产品目标

用户连接自己的钱包，选择受支持的USDT/USDC，输入包含全部费用的总支出，核对HL地址、预计净到账和最低到账，再由本人确认必要签名。链上手续费由平台或接入的代付服务先承担，用用户确认的稳定币费用回收成本并收取Perpex服务费。用户无需先去购买ETH/TRX，但必须有足够稳定币覆盖本金及全部费用。

首次授权、必要的额度清零、实际入金及费用收取都必须覆盖。只给最终deposit代付、让第一次approve仍要求ETH，不满足本需求。仅在真实验证通过的链/token/钱包组合显示“无需准备原生手续费币”。

## 已核实的可行路径

| 路径 | 能解决什么 | 不能推定的内容 |
|---|---|---|
| 钱包自身的代币付Gas | MetaMask官方列出Ethereum USDT可为符合条件的dapp交易支付网络费；需满足钱包设置及具体交易条件 | 不代表本应用现有调用已兼容；相关钱包费用不是Perpex收入，不能与平台代付重复计费 |
| 兼容智能账户/钱包的Paymaster代付 | EVM可以把批准、业务调用及受约束的收费组合；Pimlico的官方token清单包含Ethereum真实USDT合约 | 支持代币不等于所有普通钱包都支持；资产已在普通地址时，不能新建另一地址就宣称解决第一笔转入Gas |
| Tron能量及带宽委托 | 后台资源池/服务可向用户账户提供执行合约所需资源 | 需覆盖完整授权/付款步骤及实际消耗；资源已委托但用户不付款时存在损失，不能承诺只补能量必定足够 |

依据：[MetaMask官方Gas Included说明](https://support.metamask.io/manage-crypto/transactions/metamask-gas-station/)、[Pimlico支持代币](https://docs.pimlico.io/guides/how-to/erc20-paymaster/supported-tokens)、[Pimlico外部钱包能力检测](https://docs.pimlico.io/guides/eip7702/external)、[Tron资源委托](https://developers.tron.network/docs/delegation)。这些资料证明机制和候选集成存在，不是Perpex完成了真实资金验证。

## EVM首轮实施选择

优先覆盖用户现有的Ethereum USDT，再扩至审核USDC和其他EVM网络。通过钱包标准能力检测选择执行方式，不通过钱包品牌标志猜测。

1. 钱包原生代币付Gas模式：独立验证其首次approve和deposit实际行为、费用来源及回执形态。不能把零ETH保护全局删除；只对验证过的执行模式改变预检。
2. 平台统一代付模式：采用经过审核的智能账户/钱包执行能力及成熟代付基础设施。钱包需具备所需批量调用和paymaster能力，用户自己确认钱包要求的账户升级或签名。没有该能力时明确不可用，不静默变成用户自付ETH。
3. 不先给任意地址无条件转ETH再等待其入金；该方式不能保证收回成本。代付前绑定本单付款人、链、token、业务金额、费用上限、收款地址、nonce和期限，并模拟执行及预留预算。

[EIP-7702](https://eips.ethereum.org/EIPS/eip-7702)提供账户授权、批量操作和赞助的机制，但账户委托具有持续影响；采用钱包认可的实现和确认流程，不引导用户盲签任意委托代码。[ERC-7677](https://eips.ethereum.org/EIPS/eip-7677)要求按钱包能力接入，且指定paymaster不意味着它最终一定支付，应以实际回执与结算证据入账。

## 报价与收费合同

- 用户输入的是总支出上限。报价分别列出：实际参与入金的来源币本金、源链代付费、路由/兑换费用、Perpex服务费、预计及最低USDC到账，显示每项币种与报价期限。
- 网络成本随Gas与原生币兑换价格变化；平台服务费独立配置固定费或比例费。未取得真实供应商费率前，不写死“全网几毛钱”或固定利润。
- 已含在上游净到账中的费用不得再次扣除。USDT与USDC按真实报价换算，不假设严格1:1。
- 总支出不能超过用户已确认的上限。成本变化超限则重新报价并确认；不能先完成deposit把用户USDT花光，再另发一笔未获确认的扣费。
- 收入台账分开记录代收链费、供应商成本、平台服务费和退款；代收链费不是平台利润。若接Relay app fee，需核实该协议路线的收费支持并扩展现有严格校验，不能直接接受任意fees数组。
- 失败费用规则必须在确认前显示。建议HL入金未成功时退还平台服务费；已产生的网络费用能否退还依据清楚标注的规则处理。跨链流程并非全链原子交易，不能承诺所有阶段失败均零成本。

## 必须改动的代码范围

| 模块 | 需要完成的变化 |
|---|---|
| 钱包/前端 | 执行能力检测、来源币总预算、总费用与净到账、用户签名、支持模式下的零原生币处理；保持多钱包pin与未知付款保护 |
| 后台代付网关 | 私密供应商凭据、受限订单授权、交易模拟、预算预留/释放、单用户及全局限额、重复请求幂等、暂停与余额不足处理；不得暴露无限制公共代付RPC |
| 收费与报价 | 收费配置、确定的收款方、费用上限、实际扣费证明、账务对账；不从已知公开HL地址擅自扣款 |
| 来源交易核验 | 保留现有普通交易验证器；新执行模式单独核对钱包批量调用或UserOperation、业务deposit、精确token Transfer、费用转账及最终确认。外层交易可能不是原from/to/calldata结构，不能简单放松现有检查 |
| 持久化/恢复 | 在广播前保存执行模式与唯一请求标识；批量ID/UserOperation hash/链上hash分别记录；超时恢复原笔，禁止再次代付、再次收费或重付 |
| 运维 | 代付服务配置与余额、成本预算、异常账务、停用开关和收款地址；当前不存在这些已启用配置 |

## 验收与启用条件

最关键验收账户必须是**有真实Ethereum USDT、ETH为0、从未授权过本路线**。本人完成报价与签名后，核实必要的首次操作全部被代付，来源本金及费用之和不超确认值，平台账务可核对，HL本单入账不少于最低值，刷新恢复不重复执行。

还须覆盖非零旧授权需清零、恰好只有总支出余额、钱包不支持能力、拒签、报价过期、Gas突涨、代付余额不足、交易回退、跨链后续失败、重复回调、多标签与重启。每条网络/钱包组合分别验收，不把普通付Gas路线测试数移作代付通过证据。

启用主网代付前需要实际服务账户/凭据、受限代付预算、费用收款地址及最终收费规则。配置通过服务器私密环境提供，不在聊天发送私钥。当前没有创建收费账户、充值代付资金、发布合约或代用户签名。
