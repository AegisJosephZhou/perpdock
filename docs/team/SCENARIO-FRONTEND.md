# 主要入金任务与本版前端补全建议

负责人：product_delivery。依据 `SCENARIO-EXPANSION.md`。本文把本版能落地的界面改动与需要先验证的资金路线分开，供主控确定共享 registry 和实现所有权；本轮未扩大代码改动范围，没有新增假路线、演示余额或钱包签名。

## 1. 用户要完成的任务

主任务是“把我现在持有的、指定网络上的资产放进我能使用的 HL 默认 Perps 账户”。用户先说资金在哪，再选网络和资产，连接对应钱包、确认接收账户和成本，最后亲自授权/付款并恢复追踪。不能把“钱包品牌”“网络”和“币种”当成同一个选择：MetaMask 中的 USDT 不一定在 Ethereum，USDT 同名也不代表同一合约。

建议保留当前单列两屏，不引入交易所式复杂面板：

1. **付款卡**：资金来源帮助 → 付款网络 → 付款资产 → 金额/真实余额 → 钱包连接与当前网络状态 → 原生手续费状态。
2. **接收卡**：固定 HL 默认 Perps / USDC，填入钱包地址或手动填写，完整地址展示、归属确认，不同地址额外确认。
3. **报价卡**：真实净到账、最低到账、费用币种、所需授权、提供方警告、签名窗口；不保证到账时间。
4. **操作区**：获取报价 → 确认订单 → 必要时清零及精确授权 → 独立付款确认。
5. **进度页**：来源确认 → 路由处理 → 本单 HL 入账核验；恢复/上报原 hash、完整凭证、明确的异常帮助。未知状态没有新付款捷径。

主按钮只推进当前必要的一步；修复网络、余额或账户的问题在对应字段旁出现，不让用户靠报错猜下一步。

## 2. 场景矩阵与本版落点

“已有”指代码路径和软件回归，不代表用户真实钱包或所有移动设备已验收。

| TronLink 持有 Tron USDT | 切到 Tron 显示 USDT/TRX，接收 HL 0x 地址单独确认，旧 Tron 订单仍回原路线 | 已有与回归覆盖 |

| 手机系统浏览器无注入钱包 | 明示该浏览器未提供所需钱包能力，给“复制当前 HTTPS 地址”；提示在已验证的钱包浏览器打开或用桌面 | 本版能力帮助可做；手机兼容列表必须据实填，不造 WalletConnect QR |
| 钱包浏览器有注入但无 Web Locks/安全上下文 | 在付款前解释缺少恢复/互斥能力并阻断，建议使用支持的浏览器 | 本版增加提前能力提示；不能降级去掉锁来“支持手机” |
| HL 地址与付款 EVM 地址相同 | 自动填空白地址，始终手动确认；不需要二次连接同一个钱包 | rc5 已有 |
| 使用自己控制的另一 HL 地址 | 完整显示两地址，保留归属和差异两次确认；修改地址失效报价 | 已有；帮助中明确不要填交易所收款地址 |
| 新 HL 账户/HL 余额为0 | 仍通过真实报价判断能否入金，展示提供方的新账户费用或限制；读到0不是失败，也不伪造最低入金要求 | 已有实时查询；本版补“新账户也以本次报价为准”帮助 |
| 地址格式有效但不能登录该 HL 账户 | 明确地址格式和余额查询不证明控制权/可交易；让用户核对自己能通过钱包使用的账户 | 本版接收地址帮助；不伪称已验证私钥归属 |
| 金额低于最小值/超上限/超真实余额 | 字段附近给出本次范围或不足原因；比例金额用整数精度，全部不超过业务上限 | 已有；扩展18位资产前先统一输入精度 |
| USDT/USDC足够但没有原生手续费币 | 展示需要 ETH/TRX/该网络原生币；如加入真实原生余额读取，0余额阻止签名并给刷新入口 | 当前显示链费但未做通用原生余额卡；本版建议钱包组提供读取接口 |
| 旧 USDT 授权非零但不足 | 告知可能有清零、精确授权及付款三个步骤，各自耗费链费；每步成功才推进 | 钱包组已实现 Ethereum 路径；前端已有费用说明 |
| 拒绝授权/付款、交易失败 | 明确发生在授权还是付款；明确拒绝可重试，未知广播不能按拒绝处理 | 原执行流程保留；帮助入口按实际状态显示 |
| 授权后报价到期 | 重新报价前说明授权仍在链上；已广播付款不能因窗口到期重付 | 已有；沿用原安全语义 |
| 签名窗口很久未关闭/广播响应丢失 | 保留 signing/unknown 锁，提示查钱包记录并上报原 hash，不自动换路线或新付 | 已有；不得改成普通“再试一次”按钮 |
| 刷新、关闭、断网、多标签 | 原浏览器恢复订单及 hash；重复点击/多标签付款锁有效，后台继续核验 | 已有；不要在帮助中承诺任意设备恢复 |
| 换设备、无痕退出、清浏览器数据 | 说明订单号/下载收据本身不代替访问令牌，不能保证自动恢复私有订单 | 本版把现有本机恢复限制写入帮助；不新增上传秘密功能 |
| Ethereum 已显示交易成功但页面等待 | 解释还在等 finalized 与本单账本核验，可能约15分钟或更久，HL可能先到；只刷新核验，不重付 | rc5 warning 已跨报价/进度展示 |
| 单条路线/RPC不可用、其他路线正常 | 当前选择显示具体不可用原因，其他真实可用路线可供新单选择；旧单不自动迁链 | 后端逐路线 availability + 当前前端控制；本版分组选择沿用 |

## 3. 本版本建议实际实施的改动

### P0：分开选择付款网络与资产

只从 `config.routes` 派生选项：先按来源网络分组，再按该网络的已审核 token 列资产；底层仍保存完整 `route.id` 并将它交给现有报价与订单接口。没有审核通过的路线不出现为可付选项；可显示不可用原因，但不能默默回退成另一条链。默认选服务端列表第一个可用路线，恢复订单始终优先订单中的 routeId。

切网络/币种须执行同一套上下文失效：余额/余额错误、报价、授权额度、两类地址确认、创建幂等缓存。保留用户金额和接收地址可以减少重填，但必须重新确认与报价。已有订单时禁切；用户明确返回重填仅适用于尚未尝试付款的原流程。

共享 registry 建议至少统一 `id/sourceChain/sourceChainId/sourceToken/symbol/decimals/walletType`，额外给真实的资产展示名与原生手续费币种。不要在前端再维护一套独立合约白名单；代币身份由网络+合约决定，不能只按 symbol。

### P0：补一个“资金在哪里 / 使用帮助”入口

在付款卡放简短入口，不改变资金路径：

- **自己的钱包**：选择实际网络与币种，连接对应钱包。
- **交易所账户**：先提到自己控制的钱包，确保网络/资产一致，到账后回本页；交易所提现不能直发本应用合约完成存款。
- **手机**：当前浏览器无可用注入时解释原因，并提供复制当前站点 HTTPS 地址；只列经过实机验证的钱包浏览器，不显示未配置的二维码/WalletConnect。
- **暂未支持的网络/币种**：明确当前列表为可用范围，不让用户直接发送资产到页面上的合约或代币地址。

可用原生 `<details>` 或一个可关闭的帮助区域，使用现有可访问标题/按钮；不打开自动外链、不请求任何秘密，也不替用户发交易。

### P0：把费用与浏览器能力缺口前移

付款卡继续明确原生费用币种；通过钱包组的同一 provider 读取**真实**原生余额后再显示数字，无法读取时显示未知和刷新，不显示0或拍脑袋给“建议足够额度”。原生余额为0可让用户查看报价，但不可开始新的授权/付款；大于0也不保证覆盖全部 gas，以钱包估算与确认结果为准。不得从 USDT 余额直接扣一个虚构 gas 金额。

在连接/准备付款时检查当前环境需要的注入接口、安全上下文与 Web Locks，给可行动的提示。不能为提高兼容率跳过现有付款锁或接收地址确认。若本版尚未提供原生余额接口，先落实准确的链费文案和能力提示，不假称已做余额预检。

### P0：新链金额精度先收口

现有金额输入按 `route.decimals` 检查，比例按钮也会保留代币全部精度。若 BNB 18位 USDT 纳入，而 API 仍只收6位输入，“全部”会产生后端拒绝的金额。先由 root 统一**业务允许输入精度**与代币链上精度：可保守统一输入最多6位，在 bigint 上向下截断快捷金额，再以代币真实 decimals 换算最小单位；链上18位不能直接改成6位。

若本版无法完成此合同与测试，暂不开放18位资产；不得在前端四舍五入造成超余额、悄悄换金额或把相同 symbol 视作同精度。

### P1：按当前状态给下一步帮助

连接失败旁给“检查钱包/重新连接”，切错网络给明确切链按钮，费用余额不足给“补充到当前付款钱包后刷新”，已广播/未知只给“查钱包原交易/上报原 hash/刷新核验”，持续核验只给订单号与公开 hash 的支持指引。没有运维支持地址时不要创建虚假的客服链接。

继续保留本单证据判定、真实 quote warnings、下载公开订单收据以及“此浏览器保存”说明；不新增将访问令牌写入 URL、复制私钥或把订单成功状态改为人工按钮的操作。

## 4. 所有权与验收建议

主控先确定真实开放路线与共享 registry；协议组负责逐路线真实报价、来源 finality 和精度验证；钱包组提供同 provider 的原生余额/能力读取以及对应交易保护；前端组再在明确所有权内实现分组选择、帮助和状态呈现。当前 App/测试不先复制一份链/token registry。

实际新增前端测试应围绕用户结果：

1. 同链切币、跨链切币均带正确 routeId，不混淆同名代币；清空旧余额/报价/确认/授权。
2. 部分路线不可用时可选项准确，未返回的网络没有假按钮；旧 Tron/Ethereum 订单按原路线恢复。
3. 输入精度、全部/比例余额、上限在6位及18位合约样本上严格向下处理，不发生倍率错误。
4. 无注入/锁定/拒绝/错误网络/缺少 Web Locks 都有明确且安全的下一步；不存在未接通的 QR 或自动签名。
5. 原生余额0、未知、读取失败、非零分别正确显示，非零不承诺足额；报价/费用使用所选链原生币。
6. 交易所来源帮助不输出平台充值地址，也不能绕过钱包授权；接收地址仍须完整确认。
7. quote失效、清零授权、付款未知、已返hash未上报、跨标签页恢复均不能因帮助/导航重入而二次付款。
8. 仅签名步骤使用真实剩余窗口，进度仅按真实状态；Ethereum等待finalized时不展示“一秒必达”或假完成。

以上自动化不代替实机钱包与小额资金验收。手机支持列表、真实链币范围、最终测试数字仍由实际证据收口；当前没有向外部团队发消息、连接钱包或改动服务器/DNS。
