## 管理员先确认实际拓扑

推荐现成配置运行于独立 Linux + Docker Engine / Compose：Internet → Caddy → 单实例 Node 24 应用 → SQLite 持久卷。只有 Caddy 发布 80/443，应用 8787、开发 5173 和管理 2019 不对公网开放。

如果现有服务器已有 Nginx、Ingress、负载均衡或 CDN，**先列明真实访问路径和端口占用，再选择部署方式**。现成 public Compose 的 `TRUST_PROXY_HOPS=1` 只适用于 Caddy 直接接收访问者连接；不能在 Nginx/CDN 后面原样叠加，也不能随手增加信任跳数。复用已有反向代理需要单独检查 HTTPS origin、来源 IP 可信边界、转发头覆盖和后端不可直连；未确认前保持暂停。使用当前独立方案时，DNS 服务只解析域名，不开启 CDN 代理。

可见品牌已经改为 **Perpex**。`perpdock-public` 项目名、`perpdock-public-*` 数据卷以及既有浏览器存储键是内部持久化标识，故意保留以兼容订单与数据；不要全局替换或因改名另建空卷，也不要运行 `down -v`。此版本保持单实例，不做横向扩容。

## 三步验收与责任

### A. 管理员部署暂停环境

在目标服务器私密建立 `.env.public`、稳定订单密钥与自己的供应商凭据，配置最终确认的 `APP_DOMAIN`，保持 `PAUSE_NEW_ORDERS=true`、10–100 来源稳定币单位的单笔范围。密钥不发聊天，运维不需要任何钱包私钥或助记词。按精确手册执行配置检查、构建、Caddy `validate` 与启动；修改暂停值后必须重建应用容器，单纯 `restart` 不会载入新环境。

各来源核验使用服务端RPC环境键：ETHEREUM_RPC_URL、ARBITRUM_RPC_URL、BASE_RPC_URL、OPTIMISM_RPC_URL、POLYGON_RPC_URL、BNB_RPC_URL。默认值见env样例，运营必须验证每条网络的chainId、合约代码/精度、交易回执与finalized区块能力。真实健康gate按网络/token独立控制新报价；健康接口成功不表示全部路线可用。带API令牌的实际URL不发日志/前端/聊天，不以RPC故障为由放宽来源验证。

管理员回填：确认的 HTTPS 地址、发布版本、服务器/代理拓扑、证书与静态资源结果、真实端口暴露、实际 `/api/config` 暂停和限额值、持久卷写入权限、重建后数据保留、目标服务器备份恢复演练结果。另验证目标地区能访问供应商及主网只读接口；健康接口成功不代表入金路线健康。现有本机测试不能代替这些检查。

### B. 用户在正式 HTTPS 环境亲自小额验收

管理员先提供通过 A 项检查的暂停网址，再安排受控测试窗口，短时解除暂停，由用户本人使用自己的钱包签名；资金不由运维或开发者代签、代发。首轮按有效报价从所选资产10单位的小额开始：Ethereum/Arbitrum/Base/Optimism另备ETH，BNB Chain另备BNB，Polygon另备POL；Tron另备TRX/资源。非零旧授权不足时还可能先归零，不能把授权当作付款。逐步操作见 [资金验收步骤](ACCEPTANCE.md#用户小额验收操作)；若当前报价不允许该金额，以本次规则重新安排，不能用旧报价承诺成本。

当前实现实际检测到的EIP-1193/EIP-6963钱包选择（优先MetaMask/Rabby）与TronLink注入路径，需支持 Web Locks 的浏览器；TronLink 还需可用的 `txCheck`。连接 EVM 付款钱包后，空白 HL 接收地址可填入同一地址，但用户必须手动确认归属；另填不同地址还需二次确认。尚未完成用户真实钱包签名与本应用资金到账验收。手机已有布局检查，**手机钱包连接、授权、签名、恢复及浏览器兼容仍待实机验证**，不能把窄屏截图当成钱包支持通过；也不能宣称已具备通用 WalletConnect 路径。

验收至少保留本应用订单号、与原路线匹配的来源付款凭证（相应EVM链成功交易/收据、精确来源token Transfer与最终确认；或Tron固化且执行成功的匹配交易）、Relay 对应订单与目标交易、同目标交易/接收地址的 Hyperliquid 默认 Perps USDC 入账证据，以及输入/最低到账/实际到账数值、刷新恢复与订单凭证结果。公开账户余额或其他人的历史交易不是本单成功证据。签名或广播状态不明时按原订单恢复，不能再次付款。结束测试后重新暂停；已有订单仍继续查询与核验。

Ethereum 的最终确认与本应用核验可能约15分钟或更久，HL 可能先到账；Relay 的短处理估时不是总到账保证。等待期间保留原订单与交易 hash，不再次签名付款，不手动改成功状态。

### C. 确认结果后才开放市场测试

资金闭环及目标环境检查通过后，用户与负责团队再明确测试范围、值守人员、异常支持渠道、限额和回退方式。当前单笔100来源稳定币单位限额不是邀请权限或日累计限额，页面没有邀请码门禁；若必须只允许指定用户，需要先实现或配置并验证入口控制。不能因一次测试成功便承诺所有钱包、所有地区或异常自动退款均可用。
